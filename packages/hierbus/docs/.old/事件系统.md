# 目标：基于 eventbus 的「节点连接型」事件系统

| 模块 | 核心职责 | 对外 API（最小集合） | 依赖 |
|---|---|---|---|
| `Eventbus`（节点网络） | 管理节点、管理连接、负责事件在连接图中的传播 | `createNode()` / `register()` / `connect()` / `disconnect()` / `emit()` | `@tikkhun/eventbus`（底层事件分发） |
| `Node`（节点） | 作为树/图中的一个点，提供连接与收发事件的便捷入口 | `join()` / `connect()` / `disconnect()` / `on()` / `off()` / `once()` / `emit()` | `Eventbus` |

## 1. 需求

### 1.1 为什么

- 传统 eventbus 更偏“事件名 -> 监听器”映射，缺少“节点之间连接关系”的一等表达
- 在跨模块/跨子系统场景（例如：订单模块 -> 风控模块 -> 通知模块），希望显式描述事件的传播路径与拓扑结构（树/图）
- 节点优先级、连接关系（谁能给谁发）往往比“事件名分组”更重要

### 1.2 是什么

- 一个“节点网络”：节点之间可以 `connect / disconnect`，并可通过 `join` 形成树状结构（父子关系）
- 节点发出的事件会沿着连接图传播到可达节点（默认多跳传播），避免循环重复投递
- 每个节点可按事件名订阅自己收到的事件，并可获取事件上下文（from/to/event）

### 1.3 怎么做（验收标准）

| 验收项 | 说明 | 示例 |
|---|---|---|
| 节点可创建并注册 | 支持 `eventbus.createNode({ name })` | `const a = eventbus.createNode({ name: 'a' })` |
| 节点可连接/断开 | 支持单向/双向连接 | `a.connect(b)` / `a.disconnect(b)` |
| 支持树状 join | `parent.join(child)` 默认双向连接，维护 parent/children | `a.join(b); b.join(c)` |
| 支持事件传播 | `a.emit('ping')` 能传到可达节点 | `b.on('ping', ...)` |
| 去重防循环 | 双向连接不应导致无限传播 | `a.join(b)` 后 `a.emit()` 只触发一次 |
| 优先级顺序 | 同一层多个目标按 `priority` 从高到低投递 | `priority: 10` 先收到 |

## 2. 设计（API 与行为）

### 2.1 为什么（设计取舍）

- **底层分发复用 `@tikkhun/eventbus`**：它提供基于分隔符的事件名匹配与 `on/off/once/emit`，稳定且足够轻量
- **连接拓扑放在 `Eventbus` 里**：连接是全局图数据结构，集中管理更容易做去重、排序、可视化
- **Node 提供“糖”API**：业务侧只关心 `join/connect/emit/on`，不需要操作底层 bus

### 2.2 是什么（核心数据结构）

| 数据 | 位置 | 说明 |
|---|---|---|
| `nodes: Map<string, Node>` | `Eventbus` | 节点注册表，key 为 `String(node.name)` |
| `edges: Map<from, Map<to, ConnectOptions>>` | `Eventbus` | 有向边表，存储连接关系与可选过滤配置 |
| `parent/children` | `Node` | 仅用于表达“树”的语义（join），事件传播仍以 edges 为准 |

### 2.3 怎么做（事件传播规则）

| 规则 | 行为 |
|---|---|
| 起点 | `source = emit()` 的节点 |
| 传播 | 沿 `edges` 做 BFS，多跳可达节点都会收到 |
| 去重 | `visited` 集合确保每个节点最多收到一次（避免双向连接造成循环） |
| 顺序 | 对同一 `from` 的多个 `to`，按 `to.priority` 从高到低投递 |
| 上下文 | 每次投递附加 `ctx = { from, to, event }` 作为最后一个参数 |

## 3. 最小化示例（配置 + 运行）

### 3.1 为什么

- 用最小代码展示“树状 join + 多跳传播 + ctx”

### 3.2 是什么

- 创建 3 个节点形成 `a -> b -> c`（双向 join），从 `a` 发事件，`b/c` 接收

### 3.3 怎么做

```ts
import { Eventbus } from '@tikkhun/event';

const eventbus = new Eventbus();

const a = eventbus.createNode({ name: 'a' });
const b = eventbus.createNode({ name: 'b' });
const c = eventbus.createNode({ name: 'c' });

a.join(b);
b.join(c);

b.on('ping', (value, ctx) => {
  console.log('b got', value, ctx);
});
c.on('ping', (value, ctx) => {
  console.log('c got', value, ctx);
});

a.emit('ping', 1);
```

运行（在仓库根目录）：

```bash
pnpm --filter @tikkhun/event dev
```
